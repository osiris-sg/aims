## Prerequisites

- Node 20+, npm
- Access to the Neon dev database (`api-server-production/.env`) and Clerk dev keys
- No local Postgres needed — all three environments run on Neon branches

## Backend (`api-server-production/`)

```bash
npm install
npm run start:dev          # dev server with watch mode (port 4040)
npm run start:staging      # dev server against .env.staging
```

### Database commands

There are **three separate Neon databases** — dev (`.env`), staging (`.env.staging`), prod (`.env.production`). Every DB command has env-targeted variants; hitting the wrong one 500s the app.

```bash
npm run db:push            # push schema to DEV
npm run db:push:staging    # push schema to STAGING
npm run db:push:prod       # push schema to PROD
npm run db:studio          # Prisma Studio (also :staging / :prod)
npm run seed               # seed permissions + osiris-platform org
```

<Warning>
`npm run build` is **not** a plain compile — it runs `nest build && npx prisma db push`, mutating whatever database `DATABASE_URL` points at. Use `npx nest build` for a compile-only check.
</Warning>

### Testing & quality

```bash
npm run test               # unit tests (also test:watch, test:cov)
npm run test:e2e           # e2e tests
npm run lint               # ESLint with auto-fix
npm run format             # Prettier
```

### Admin scripts

```bash
npm run assign-superadmin    # per-org superadmin role
npm run assign-osirisadmin   # global platform admin (admin@osiris.sg)
npm run debug-user-roles
npm run setup-database / setup-user
```

There are ~40 more one-off scripts in `package.json` (template seeders, nav migrations, data backfills, `render-env:*` sync). Destructive ones follow a `:dry` / `--dry-run` convention — **always run the dry variant first**. The `scripts/` directory itself holds ~700 files; `_`-prefixed files are one-off forensic scripts, unprefixed ones are named operational scripts.

## Frontend (`portal-production/`)

```bash
npm install
npm run dev                # Next.js dev server with --turbo
npm run build              # production build (safe — no DB side effects)
npm run lint
```

Env keys (`.env.example`): `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`, `NEXT_PUBLIC_BACKEND_API_URL`, `NEXT_PUBLIC_RESOURCE_URL` (S3).

## Swagger

With the backend running, interactive API docs are at `http://localhost:4040/api` — bearer auth (Clerk JWT) plus an `X-Api-Key` scheme for the external `/v1` API.
